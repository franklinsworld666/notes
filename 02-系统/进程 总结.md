父进程，子进程，哪个先调用，是不确定的。

  

fork() 失败的可能原因：资源问题，比如进程数量达到上限了，该USERID上的资源不足了

  

通常的做法，先fork，再执行exec  

  

经由 fork 创建的子进程，其中只有一个线程，对应着主进程里调用fork函数的线程。此外，主进程的整个虚存空间都被复制到了子进程。

  

子进程继承了哪些资源？

子进程有自己独立的进程空间，写时拷贝方式复制了父进程的 text, data, heap , stack

  

其他资源：

- file descriptors: 父子进程会指向内核中 open file table 中的同一项，共享偏移量、file status flag
    

![](进程%20总结-20260911132019711-1.png)  

  

- user-space buffer： 子进程继承了父进程的标准IO缓冲，kernel中的buffer则无法继承
    
- exit handler:  子进程继承父进程的 exit handler，在执行exit时调用

进程如何终止

进程退出的2种方式：

-  exit(status)
    
-  main 函数中执行 return ， 会调用 exit
    

  

进程退出时会做些什么：

- exit handler
    
- flush stdio buffer
    
- _exit(status)
    

  

进程退出时，释放那些资源：

- 文件描述符，关闭
    
- 文件锁，释放
    
- mmap() 的内存释放
    
- POSIX 信号量
    
- POSIX message queues
    

  

存在父子进程时，怎么退出？怎么避免复制不必要的东西

- 父进程 exit, 子进程 _exit, 
    
- fork() 前 flush， fork后设置 exit handler

如何回收子进程资源

+ 方法一：wait

+ 方法二：waitpid

+ 方法三：sigchild  + wait/waitpid

  

如果子进程结束

+ 父进程没有 wait，子进程就成为zombie，zombie无法kill，会在process table 中占用一个 entry （包括：子进程id，退出状态，资源使用情况）

+ 父进程可以在子进程退出之后，再wait，一样可以回收子进程的资源

+ 如果子进程是zombie，父进程退出后，init进程就成为了子进程的parent，这时init进程会来回收资源

system 实现

The system() function creates a child process that invokes a shell to execute command.

  

Avoid using system() in set-user-ID and set-group-ID programs  --- 存在安全漏洞

  

system 实现的复杂，主要在于信号的处理 --- sigchld，sigint，sigquit

  

关于system（）：

1. 先创建一个子进程去执行 shell；shell 进程里执行 cmd 命令

2. 上述步骤，意味着会多出2个进程

3. 调用进程，会等待子进程的结束并获取状态 waitpid

  

关于 system() 返回值:

1. 如果系统调用全部执行，会返回最后一条命令的退出状态；

2. 其他情况，如：创建进程失败、无法执行shell等，会返回-1,127,128+N

关于 popen 

1. 先创建一个子进程去执行 shell；shell 进程里执行 cmd 命令；同时创建一个管道，读或写

2. 上述步骤，意味着会多出2个进程

3.  优点：可以通过管道获取 cmd 的输出；或向其发送输入

4. 返回值：失败，返回 NULL，通过 errno 查看错误

  

关于 pclose：

1. 调用进程，等待子进程结束并获取状态 waitpid

2. 返回值：返回结束状态，或者 -1

  

如何判断 cmd 命令执行成功与否：

根据 pclose 的返回值，失败：-1；成功，返回结束状态，再用 WEXITSTATUS(status) 获取

其他

process credentials

- real user ID / real group ID
    

When a user logins, it gets a real user ID from /etc/passwd. When a process is created, it inherits these IDs from its parent.

  

Real user ID / real group ID tell us the owner of a specific process.

  

- Effective user ID / group ID
    

Effective user ID / effective group ID determines the permissions of a process.

  

Generally, effective user ID == real user ID; 

  

There are two ways we can change it. 

+ Program A , owned by root, has set its set-user-id bit. User B executes program A, then A's real user id == B, A's effective user id == root, A's saved-user-id == root

  

+ setuid() etc

  

- saved-set-user-id / saved-set-group-id
    

An unprivileged process can change its effective user id between real user id and saved-set-user-id.

  

These ids are copied from the corresponding effective user id. 

  

- set-user-id bit
    

chmod u+s prog

chmod g+s prog

-rwsr-sr-x prog

  

- File-system user ID / File-system group ID
    

On linux, it is these ids that determine the permissions of a process, not effective user id.

Normally,  == Effective user ID / Effective Group ID

They are different only when we use setfsuid() / setfsgid() to change it.

  

- How to find a process's ids
    

cat /proc/pid/status

  

|   |   |   |   |   |
|---|---|---|---|---|
||real|effective|saved-user-id|file-system|
|UID|||||
|GID|||||

- retrieve real user id, effective user id
    

getuid(), getgid()

geteuid(), getegid()

  

seteuid() : 特权进程，可以改成任意 ID，会暂时失去特权；但可以通过把 effective user id == real user id，regain privilege  ; 非特权进程，仅能在 real user id , saved-user-id 间切换

  

process resources

+ /proc/pid/  : 这个文件下，包含了有关进程的各种信息

+ /proc/pid/task/tid : 有关线程的各种信息

+ /proc/pid/status: 可能是关于进程的最重要的文件

+ /proc/net : 网络状态信息等

+ /proc/sys/net : 网络配置

+ /proc/sys/fs  : file system

+ /proc/pid/stat ： 有关于这个进程的 pid，ppid，pgid，sid等的信息；每个值的含义见 “man 5 proc”

  

  

process groups, sessions

+ process group: one or more processes that share the same pgid. PGID 是创建这个进程组的进程的pid

  

+ session：a collection of process groups. sid 创建这个session 的进程pid

  

+ 同一个session中的进程，共享同一个控制终端。但只有foreground process group 才能和终端交互，每次在终端输入时，信号会被发送给前台进程组的每一个进程。

  

+ 终端断开时，会发送 SIGHUP 给自己的控制进程 --- 本会话的创建者，即打开这个终端的进程

  

+ 子进程，继承父进程的 pgid，sid
