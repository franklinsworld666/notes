    

# 信号 总结

信号，提供了一种异步事件通知和处理机制。

应用场景：事件通知、作业控制、定时器超时、进程同步

  

## 信号机制

### 何种情况下产生信号

- 硬件事件：除数为0，内存越界访问
    
- 软件事件：套接字有数据可读，倒计时到了等
    
- 用户发出：ctrl+C (SIGINT)，ctrl+\ (SIGQUIT),  ctrl+Z(SIGTSTP)
    
- 一个进程向另一个进程发信号
    

  

### 谁发出信号

- 内核：比如当除数为0，内核发出信号
    
- 用户：比如用户在终端按 ctrl + C
    
- 一个进程给另一个发
    

  

### 信号是同步还是异步

一般，信号是异步的。2种特殊情况下是同步的：

- 自己向自己发信号
    
- 本进程发生硬件异常
    

### 信号的状态

- 产生
    
- pending（等待）
    
- delivered（到达）
    

  

### 信号如何传递

- 同步信号：信号产生以后，立即发出
    
- 异步信号：下一次内核态切换到用户态时，发出。所以，会有个产生 --- 等待 --- 传递到达的过程。
    

  

### 阻塞信号

可以通过设置掩码来阻塞信号。本质上，这个掩码是线程的一个属性。

一旦信号被阻塞，那么信号产生以后会处于“pending" 状态，直到解除阻塞。

当信号阻塞的时候，如果又来了同样的信号，他们并不会排队，阻塞解除后，只会递送一次。

另外，一般来说，当信号A被捕获的时候，会自动设置掩码阻塞A，捕获函数结束后恢复。这样，在执行A的捕获函数时，执行过程不会被同一个信号打断。

  

### 解除阻塞后，信号的传递顺序

- 立即传递信号，按信号的升序传递
    
- 在执行第一个信号捕获函数时，如果发生内核态到用户态切换，会被第2个信号打断

### 怎么处理到达的信号

- 忽略
    
- 终止进程
    
- 终止进程并产生 core
    
- suspend 进程：信号 SIGSTOP
    
- 继续执行进程：信号 SIGCONT
    
- 用户自定义的信号捕获函数，有些信号是不能被捕获的
    

  

### 信号到达后处理流程

这里，执行捕获函数的还是同一个进程。只是执行流程被信号改变了。可以通过在信号捕获函数里打印 pid 确认。

### 重点信号介绍

- SIGABRT
    

abort() 产生该信号，而且会终止程序。如果信号第一次产生后，被捕获了没有终止，那么当从捕获函数返回时，abort() 会把 SIGABRT 的处理方式重置为默认方式，然后发出第二次 SIGABRT 信号。

  

- SIGCHLD
    

一个子进程终止时，会给父进程发送这个信号。还有一种情况，子进程停止运行或继续运行，也会发出这个信号。

  

- SIGHUB
    

终端断开时，会发这个信号给当前终端的控制进程。

另一个用途，给 daemon 进程发 SIGHUB，然后 daemon 进程重新去读配置。为什么可以这样？因为 daemon 进程本来就没有终端，正常是不可能收到 SIGHUB 的。

  

- SIGKILL 和 SIGSTOP
    

这两个信号，不能捕获。

  

- SIGPIPE
    

This signal is generated when a process tries to write to a pipe, a FIFO, or a socket for which there is no corresponding reader process.

  

- SIGTERM
    

在终止进程时，建议优先采用 SIGTERM。因为，一个好的程序，会设置 SIGTERM 捕获函数保证程序优雅地终止，比如：清理临时文件、释放各种资源。SIGKILL 应该作为最后的手段。

### 用 kill 发出信号

#include <signal.h> // Return 0 on success, or -1 on error int kill(pid_t pid, int sig);

  

- pid > 0, 发送给该进程
    
- pid == 0, 发送给有权限的同一个组的进程（排除内核进程 + init）
    
- pid < 0, 发给组ID等于|pid|的进程，要有权限，排除内核进程+init
    
- pid==-1，发送给有权限的所有进程，排除内核进程+init
    
- sig == 0， 可以检测进程是否存在
    

  

一个进程发信号给另一个需要有权限：

- 超级用户可以发给任何进程
    
- 非超级用户：发送者的 real user id / effective user id = 接收者的 real user id / saved set-user-id
    

  

关于实际用户ID，有效用户ID，和设置用户ID：

- 一般，有效用户ID = 实际用户ID
    
- 用户A访问用户B所有的文件，不让访问。那么如何让A可以访问呢？一个办法是，该文件增加“设置用户ID”或“设置组ID”位，当A访问时，有效用户ID就被设成B，然后就可以访问了。
    
- saved set-user-id: 有效用户 ID 被修改时，这个也会被修改为 effective ID ，这样就可以在 real ID 和 Effective ID 之间切换
    

  

### 其他发出信号的方式

- raise：用来给自己发信号
    
- killpg：发信号给某个进程组的全部进程
    

  

### 用 sigprocmask 阻塞信号

sigprocmask 可以干什么？

- 添加需要阻塞的信号
    
- 去掉一个不用阻塞的信号
    
- 获取当前的掩码
    

  

相关的函数：

int sigemptyset(sigset_t *set); int sigfillset(sigset_t *set); int sigaddset(sigset_t *set, int sig); int sigdelset(sigset_t *set, int sig); int sigismember(const sigset_t *set, int sig); int sigprocmask(int how, const sigset_t *set, sigset_t *oldset); int sigpending(sigset_t *set);

  

例子：

sigset_t blockSet, prevMask; /* Initialize a signal set to contain SIGINT */ sigemptyset(&blockSet); sigaddset(&blockSet, SIGINT); /* Block SIGINT, save previous signal mask */ if (sigprocmask(SIG_BLOCK, &blockSet, &prevMask) == -1) errExit("sigprocmask1"); /* ... Code that should not be interrupted by SIGINT ... */ /* Restore previous signal mask, unblocking SIGINT */ if (sigprocmask(SIG_SETMASK, &prevMask, NULL) == -1)     errExit("sigprocmask2");

### 用 sigaction 设置捕获函数

struct sigaction { void (*sa_handler)(int); /* Address of handler */ sigset_t sa_mask; /* Signals blocked during handler invocation */ int sa_flags; /* Flags controlling handler invocation */ void (*sa_restorer)(void); /* Not for application use */ }; // return 0 on success, -1 on error int sigaction(int sig, const struct sigaction *act, struct sigaction *oldact);

  

- sa_handler: 捕获函数
    
- sa_mask: 捕获函数执行期间，要阻塞的信号。当前捕获函数对应的信号，会自动阻塞。执行完毕后，恢复。
    
- sa_flags: 控制标志
    
- SA_NODEFER： 一个信号被捕获时，不会自动加入阻塞队列。即捕获函数可能被同一个信号打断。
    
- SA_RESETHAND：信号被捕获时，把处理方式恢复默认
    
- SA_RESTART：自动重启被中断的系统调用，但不是所有的系统调用都可以
    

  

### 异步信号安全的捕获函数

由于信号可能在任何地方打断程序的正常执行，所以捕获函数必须要是：

- 可重入的
    
- 不会被信号捕获函数打断，比如：阻塞相关信号
    

  

如果可能影响 errno ，还要有进一步处理:

void handler(int sig) { int savedErrno; savedErrno = errno; /* Now we can execute a function that might modify errno */ errno = savedErrno; }

  

在 main program 和 signal handler 之间共享的全局变量，应该按照如下声明：

// volatile : 告诉编译器不要优化这个变量 // sig_atomic_t: 对变量的读写是原子操作。++，-- 这个操作不保证是原子的。 // flag = XXX; // if (flag == XXX) volatile sig_atomic_t flag;

## 其他

- 信号的实际值，和具体的实现有关，不同系统不一样
    
- 标准信号：1～31
    
- 实时信号：32+
    
- 查看当前系统的信号：`kill -l`
    
- 查看进程中哪些信号被阻塞、在等待
    

`cat /proc/pid/status`

  

- 不建议用 signal 函数捕获信号，因为移植性不好，采用 sigaction 替代。
    
- 打印信号的描述信息
    
      
    

// 不建议在 捕获函数中调用，非可重入函数 char *strsignal(int sig); void psignal(int sig, const char *msg);

  

- when the disposition of a pending signal is changed to be SIG_IGN, the program never sees (catches) the signal.
    

  

- 如果出现因为栈空间不够了，导致段错误，这时候也是无法进入捕获函数的，因为没有空间给捕获函数了。解决方案：预先给捕获函数分配一块空间，signalstack + SA_ONSTACK
    

  

- 要想获取关于信号的更详细信息，采用 SA_SIGINFO
    

struct sigaction { union { void (*sa_handler)(int); void (*sa_sigaction)(int, siginfo_t *, void *); } __sigaction_handler; sigset_t sa_mask; int sa_flags; void (*sa_restorer)(void); }; #define sa_handler __sigaction_handler.sa_handler #define sa_sigaction __sigaction_handler.sa_sigaction   struct sigaction act; sigemptyset(&act.sa_mask); act.sa_sigaction = handler; act.sa_flags = SA_SIGINFO; if (sigaction(SIGINT, &act, NULL) == -1) errExit("sigaction");

  

- core 文件没有产生：系统限制了文件大小、系统限制了 core 大小；进程没有在目录里写文件的权限；用户A利用文件B的设置用户ID去执行文件B的，B进程此种情况下是不会产生core的；
    

  

- 信号捕获函数在 exec 启动的一个新进程中不起作用，因为：虚拟内存空间不一样了
    
- 信号捕获函数在子进程中，起作用，因为：子进程和父进程虚拟空间一致
    
- SIGSTOP 和 SIGCONT 的处理和其他信号有所不同，具体请查书
    

  

实现信号特点：

- 队列化。多次收到同一个信号，会传递多次
    
- 传递顺序。按编号从小到大，同一个编号按发生顺序。
    
- 排队实时信号的数量有限制。
    

  

- sigsuspend
    

unblock 一个信号，并阻塞在那里等待某个信号，这是一个原子操作。

返回值：-1，当从信号捕获函数返回，sigsuspend随之返回，并恢复掩码
